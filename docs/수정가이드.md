# 알음알음 수정 가이드

> 안양 동안구 학원 소개 앱 '알음알음' 베타 데모의 설치 · 사용 안내와, 소스를 직접 고치실 때 보는 문서입니다.
> 화면이 늘어날 때마다 이 문서도 함께 채웁니다. **현재: v0.3 (2026.10.22) — 전체 탭 시연판(가입 · 탐색 · 학원 상세 · 수강료 · 라운지 · 상담 · 알림장 · 알림 · 요금제)**

## 0. 이번 버전 안내 (v0.3)

### 설치
1. 함께 보내 드린 `알음알음_v0.3.apk` 를 휴대폰으로 옮깁니다 (카카오톡 '나에게 보내기' 또는 USB).
2. 파일을 눌러 설치합니다. '출처를 알 수 없는 앱' 경고가 나오면 이 파일에 한해 설치를 허용해 주세요. (Play 스토어를 거치지 않은 테스트용 APK라 나오는 안내입니다)
3. 안드로이드 7.0 이상에서 동작합니다.

- 지역은 평촌동 · 호계동 · 관양동 · 비산동, 대상 나이는 초1-2 · 초3-4 · 초5-6 · 중등 · 고등 · 성인, 과목은 국어 · 영어 · 수학 · 과학 · 미술 · 논술 · 코딩 · 외국어 · 입시입니다.
- 엑셀에서 '확인필요'인 칸(주소 · 셔틀 등)은 앱에 **'미정'** 으로 보입니다.

### 실제로 저장되는 것 · 시연용인 것

처음 말씀 나눈 대로 시연(MVP) 목적에 맞춰 나눴습니다.

| 구분 | 화면 | 저장 |
|---|---|---|
| 실제 저장 (Firebase) | 회원가입 · 로그인, 학원 200곳 · 필터 · 검색, 학원 상세 정보 · 가격, 반별 수강료 | 여러 휴대폰에서 같은 데이터를 봅니다 |
| 시연용 (예시 데이터) | 라운지, 상담 · 채팅 · AI 상담노트, 알림장, 알림 센터, 학원 리뷰, 관계자 출결 · 알림장 보내기 | 그 휴대폰 안에서만 바뀌고, 앱을 다시 열면 처음 상태로 돌아갑니다 |

- 시연 화면의 예시 학원(바른수학 · 리딩트리 영어 · 피아노 하우스 · 생각하는 수학교실)은 실제 동안구 학원과 겹치지 않는 가상 이름입니다. 실제 학원에 가짜 후기가 붙지 않도록 리뷰는 비어 있는 상태에서 시작합니다.
- 상담 채팅은 보내면 잠시 뒤 학원 쪽 자동 답장이 옵니다(시연용).
- 홈의 '오늘의 알림장' 카드와 '다가오는 설명회 · 레벨테스트' 목록도 시연용 예시입니다.
- 학원 상세의 소식 · 선생님 · 셔틀 노선은 넣지 않았습니다.
- 웹에서 주소로 바로 들어가거나 새로고침하면 하위 화면 왼쪽 위에 '홈' 버튼이 보입니다(돌아갈 화면이 없을 때).

### 테스트하실 때 참고
- 회원 · 학원 · 반별 수강료는 여러 휴대폰에서 같은 데이터를 봅니다(서버 저장). 한 분이 가입하면 다른 분 휴대폰에서도 그 계정으로 로그인할 수 있습니다.
- 한글 아이디는 로그인 서버(Firebase)가 이메일 형식만 받아서, 내부에서 영문 코드(`k.` + 16진수)로 바꿔 저장합니다. 로그인할 때는 한글 그대로 입력하면 됩니다.
- 학원 관계자로 가입하면 서류 확인 전 상태(`인증 대기`)로 만들어집니다. 서류 확인 처리는 운영자가 Firebase 콘솔에서 합니다(8장 참고).
- 반별 수강료는 **가입할 때 고른 학원**의 관계자만 등록 · 수정할 수 있습니다. 데모라서 서류 확인 전 관계자도 입력할 수 있게 두었습니다. 실제 서비스 전에는 서류 확인된 관계자만 입력하도록 바꾸는 것을 권합니다(보안 규칙의 `isStaffOf`).
- 학원 목록이 새 엑셀(학원ID H001~H200)로 바뀌어서, v0.1 때 만든 학원 관계자 · 학생 테스트 계정은 예전 학원을 가리킵니다. 새로 가입해서 테스트해 주세요.
- 불편한 점 · 바꾸고 싶은 점은 화면 이름(예: '1-3a 학부모 프로필')과 함께 알려 주시면 빠르게 찾습니다.

## 1. 사용 언어와 기술

| 구분 | 쓰는 것 | 하는 일 |
|---|---|---|
| 앱 | **Flutter 3.44 / Dart 3** | 화면과 동작 전부. 안드로이드 APK로 빌드 |
| 로그인 | **Firebase Authentication** | 아이디 · 비밀번호 로그인. 가입 화면에 들어오면 임시(익명) 로그인을 하고, 가입을 마칠 때 아이디 계정으로 바꿉니다 |
| 데이터 | **Cloud Firestore** (서울 리전, 무료 Spark 요금제) | 회원 · 학원 · 글 · 상담 · 알림장 저장 |
| 보안 | **Firestore 보안 규칙** (`firestore.rules`) | 누가 어떤 데이터를 읽고 쓸 수 있는지 서버에서 막음 |
| 학원 등록 도구 | **Node.js** 스크립트 (`tools/import_academies`) | 학원 엑셀(xlsx)을 Firestore에 올림 |
| 글꼴 | **Pretendard** (SIL 오픈 폰트 라이선스, 무료) | 앱 전체 글꼴 |

### 앱 안에서 쓰는 Flutter 패키지

| 패키지 | 용도 |
|---|---|
| `firebase_core`, `firebase_auth`, `cloud_firestore` | Firebase 연결 · 로그인 · 데이터 |
| `provider` | 화면과 데이터 상태를 이어 주는 도구 |
| `go_router` | 화면 주소(경로)와 이동 |
| `flutter_localizations` | 한국어 날짜 · 버튼 문구 |
| `url_launcher` | 학원 상세의 전화 걸기 · 홈페이지 열기 |
| `fake_cloud_firestore`, `firebase_auth_mocks` | 테스트 전용 (앱에는 안 들어감) |

### 왜 이렇게 골랐나
- **Flutter**: 화면 하나가 파일 하나라 찾아 고치기 쉽고, 나중에 iOS가 필요하면 같은 소스로 만들 수 있습니다.
- **Firebase**: 서버를 직접 운영하지 않아도 여러 테스터가 동시에 가입하고 글을 쓸 수 있습니다. 테스트 규모에서는 비용이 들지 않습니다.
- **코드 생성 도구를 쓰지 않음**: 데이터 클래스를 손으로 써 두어서, 별도 빌드 명령 없이 바로 읽고 고칠 수 있습니다.

## 3. 실행 · 빌드

```powershell
# 휴대폰에서 바로 실행 (저장하면 화면이 바로 바뀌는 개발 모드)
flutter run

# 테스터에게 보낼 APK 만들기 → build\app\outputs\flutter-apk\app-release.apk
flutter build apk --release

# 코드 검사와 테스트
flutter analyze
flutter test
```

### 웹으로 빌드 · 배포 (Firebase Hosting)

웹 설정(`web/`, `firebase_options.dart` 의 web, `firebase.json` 의 hosting)이 들어 있어 같은 소스로 웹도 만들 수 있습니다.

```powershell
flutter build web --release

# 확인용 미리보기 주소(기존 주소는 그대로, 30일 뒤 닫힘)
npx -y firebase-tools@latest hosting:channel:deploy <채널 이름> --expires 30d

# 기본 주소(alumalum-demo.web.app)에 올리기
npx -y firebase-tools@latest deploy --only hosting
```

- 앱 파일은 매번 새로 받도록(`Cache-Control: no-cache`) 설정해 두어, 다시 배포하면 새로고침만으로 바뀐 화면이 보입니다.
- 결과물 확인과 오류 수정은 안드로이드 APK 기준입니다. 웹에서만 생기는 화면 차이는 따로 확인이 필요합니다.

> Windows에서 빌드가 `Could not close incremental caches` 오류로 멈추면: 이미 `android/gradle.properties` 에 `kotlin.incremental=false` 를 넣어 두었습니다. 지우지 마세요.

## 4. 폴더 구조

Flutter 공식 권장 구조(화면 · 상태 · 데이터 분리)를 따릅니다.

```
lib/
├── main.dart                     앱 시작: Firebase 연결, 공용 객체 등록
├── firebase_options.dart         Firebase 프로젝트 연결 정보
├── routing/router.dart           화면 주소표 · 로그인 여부에 따른 이동
├── data/
│   ├── services/auth_service.dart          로그인 · 가입 · 임시 로그인
│   └── repositories/                       Firestore 읽기 · 쓰기
│       ├── user_repository.dart            회원 · 자녀 연결 코드
│       └── academy_repository.dart         학원 목록 · 반별 수강료
├── domain/models/                데이터 모양 (학원, 회원, 자녀)
└── ui/
    ├── core/theme.dart           ★ 색 · 글꼴 · 글자 크기
    ├── core/widgets/             공통 부품 (버튼, 칩, 입력칸, 학원 아이콘)
    └── features/<기능>/
        ├── views/                화면
        └── view_models/          화면 상태와 동작 (입력 검사 등)
web/                              웹 빌드용 설정 (index.html, 아이콘)
firestore.rules                   보안 규칙
tools/import_academies/           학원 엑셀 등록 도구
tools/rules_test/                 보안 규칙 테스트
test/                             앱 테스트
```

**고칠 때의 원칙**: 화면 모양은 `views/`, 버튼을 눌렀을 때 동작과 입력 검사는 `view_models/`, 데이터를 어디에 어떻게 저장하는지는 `data/` 에서 고칩니다.

## 7. 학원 리스트 등록 · 수정

학원 정보는 엑셀(`동안구_학원정보_200_최종.xlsx`)이 원본입니다. 엑셀을 고쳐서 다시 올리면 됩니다.

```powershell
cd tools\import_academies
npm install                                      # 처음 한 번
gcloud auth application-default login            # 처음 한 번: 업로드 권한(Firebase 프로젝트 권한이 있는 Google 계정)

# 1) 미리보기: 업로드하지 않고 preview.json 만 만든다. 개수와 지역 · 규모별 수가 출력된다
node import.mjs "..\..\docs\20261022\동안구_학원정보_200_최종.xlsx"

# 2) 업로드: 학원ID가 같으면 엑셀에 있는 칸만 갱신한다
node import.mjs "..\..\docs\20261022\동안구_학원정보_200_최종.xlsx" --upload

# 3) 교체: 위에 더해, 엑셀에 없는 학원(빠진 학원 · 예전 ID)을 지운다
node import.mjs "..\..\docs\20261022\동안구_학원정보_200_최종.xlsx" --upload --replace
```

- 읽는 시트: `학원목록(…)`(학원 한 줄씩, 머리글 두 줄)과 `학원비(교육청 등록)`(교습과정 한 줄씩). 나머지 시트는 읽지 않습니다.
- 대상 나이 · 과목은 해당 칸에 **O** 를 적으면 들어갑니다. '확인필요'나 빈칸은 앱에 '미정'으로 보입니다.
- 학원비 시트에서는 '요약 반영'이 O 인 정규 과정만 학원 상세에 보입니다.
- 학원 관계자가 앱에서 입력한 반별 수강료(`classes`)는 업로드 · 교체 때 지워지지 않습니다. 단, `--replace` 로 학원 자체가 지워지면 그 학원의 수강료는 앱에서 보이지 않게 됩니다.
- 엑셀 열 이름이 바뀌면 `tools/import_academies/convert.mjs` 맨 위의 `COL` · `AGES` · `SUBJECTS` 만 고치면 됩니다.
- 외부 사이트 후기 평점 · 조사 메모 · 판단 근거는 `academies_meta` 에 따로 저장되고 앱에서는 보이지 않습니다.

## 8. Firebase 보는 법

- 콘솔: <https://console.firebase.google.com/project/alumalum-demo> (현재 개발사 계정 소유. 납품 때 의뢰인 계정을 소유자로 추가하고 개발사는 빠집니다)
- **Authentication → 사용자**: 가입한 회원. 아이디는 `<아이디>@alumalum.app` 형태로 보입니다(실제 메일은 보내지 않음). 이메일 없이 '익명'으로 보이는 회원은 가입을 시작했다가 끝내지 않은 임시 계정입니다.
- **Firestore → 데이터**

| 컬렉션 | 내용 | 앱에서 읽기 |
|---|---|---|
| `users/{uid}` | 회원 공개 정보 (역할, 닉네임, 동네, 자녀, 관심 과목) | 본인만 |
| `users/{uid}/private/info` | 휴대폰, 이메일, 동의 항목, 서명 이미지, 자녀 연결 코드 | 본인만 |
| `linkCodes/{6자리}` | 자녀 연결 코드 → 보호자 | 코드를 아는 사람만 1건 |
| `academies/{학원ID}` | 학원 정보 · 교육청 등록 교습비 | 로그인한 사람 |
| `academies/{학원ID}/classes/{자동}` | 학원 관계자가 등록한 반별 수강료 | 로그인한 사람 (쓰기는 그 학원 관계자만) |
| `academies_meta/{학원ID}` | 외부 후기 · 조사 메모 | 불가 |

- **학원 관계자 서류 확인**: 관계자 회원은 가입 직후 `verified: false` 입니다. 서류를 확인한 뒤 Firestore 콘솔에서 해당 `users` 문서의 `verified` 를 `true` 로 바꿔 주세요. 앱에서는 본인이 바꿀 수 없게 막혀 있습니다.

## 9. 보안 규칙 고치기

`firestore.rules` 를 고친 뒤에는 반드시 테스트를 돌리고 배포합니다.

```powershell
cd tools\rules_test
npm install                 # 처음 한 번 (Java 가 필요합니다)
npm test                    # 로컬 에뮬레이터에서 규칙 테스트 (현재 22개)

cd ..\..
npx -y firebase-tools@latest deploy --only firestore:rules

# 배포 뒤 실제 서버에서 가입 흐름이 막히지 않는지 확인 (확인용 계정을 만들므로 콘솔에서 지워 주세요)
node tools\rules_test\live_signup_check.mjs
```

지금 규칙의 핵심:

- 회원 정보(`users`)와 개인 정보(`private`)는 **본인만** 읽습니다.
- 가입 중인 임시 계정은 학원 목록과 연결 코드 조회만 할 수 있고, 아무것도 저장할 수 없습니다.
- 학생은 보호자의 연결 코드를 실제로 알아야만 그 보호자와 연결됩니다.
- 역할 · 아이디 · 학원 관계자 서류 확인(`verified`)은 본인이 바꿀 수 없습니다.
- 반별 수강료는 가입 때 고른 학원의 관계자만 쓰고, 금액 · 시간 · 정원은 정해진 범위 안의 숫자만 받습니다.
